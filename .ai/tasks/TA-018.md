# TA-018 - Multi-mesh model assets

Status: Reverted by TA-019 (2026-08-13)

The implementation was removed at the user's request. The project intentionally returned to a one-Mesh,
one-material asset contract so the renderer stays focused on inspectable pipeline demonstrations.

## Goal

Import a GLB containing multiple Mesh objects as one editable scene model while preserving each part's UV, material, and glTF node transform.

## Acceptance criteria

1. Blender exporter accepts multiple selected Mesh objects without requiring their transforms to be applied.
2. The loader traverses the active glTF scene and preserves node transforms for static mesh parts.
3. One `SceneObject` owns one shared transform and multiple independently materialized `ScenePart` entries.
4. Renderer, shadows, picking, focus, duplicate/delete, and persistence treat the model as one scene object.
5. Old version-1 scene JSON remains loadable; new scenes persist model parts.
6. A regression test imports two transformed Mesh nodes and verifies model grouping.
7. Build, tests, Blender add-on registration, runtime smoke, and `git diff --check` pass.

## Validation

- `cmake --build --preset debug`: passed with MSVC `/W4 /WX` and DXC warnings-as-errors.
- `ctest --test-dir build/vscode -C Debug --output-on-failure`: 3/3 passed.
- The asset regression generated a glTF with two transformed Mesh nodes and verified one imported model, two parts, and transformed bounds.
- Existing version-1 scene runtime smoke: passed for four seconds.
- Blender 5.1 factory-startup add-on import, registration, and unregistration: passed.
- `git diff --check`: passed with only the existing README line-ending notice.
- A real production multi-mesh textured asset still needs manual visual validation.
