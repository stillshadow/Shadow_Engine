# TA-016 - Automatic asset discovery and Blender GLB exporter

Status: Done (2026-08-13)

## Goal

Replace manual ImGui file-path import with a predictable DCC-to-runtime asset workflow.

## Workflow

1. Editable Blender files and source textures can live in any DCC working directory and are not required by the engine repository.
2. Blender exports selected mesh objects as an embedded-texture GLB to
   `assets/models/<AssetName>/<AssetName>.glb`.
3. Shadow Engine recursively discovers `assets/models/**/*.glb` on startup.
4. The Editor can instantiate an already loaded asset but does not import arbitrary file paths.

## Acceptance criteria

1. Startup discovery loads valid GLB files and reports invalid files without aborting the application.
2. Saved `gltf://` scene references remain reloadable.
3. Blender add-on validates selected meshes/UV/materials, exports a GLB without mutating source objects, and uses
   only exporter properties supported by the installed Blender version.
4. Asset folders and Blender installation/use are documented in the canonical guide.
5. Build, tests, runtime smoke, and `git diff --check` pass.

## Validation

- `ctest --test-dir build/vscode -C Debug --output-on-failure`: 3/3 passed; the discovery regression injects an
  invalid nested GLB and verifies the failure is isolated while built-in assets remain available.
- `python -m py_compile tools/blender_addon/shadow_engine_exporter/__init__.py`: passed.
- Four-second runtime smoke with an empty `assets/models/` directory: remained running.
- `git diff --check`: passed with only the existing README line-ending notice.
- Blender UI/export execution still requires manual validation inside the user's installed Blender version.
