# TA-007 - Scene object authoring practice

## Goal

Turn the current hard-coded sphere and ground parameters into explicit, readable scene objects, then let the learner personally add a second material sphere and adjust its transform and surface parameters before continuing to Cook-Torrance PBR.

## Scope

- Group mesh range, transform, and material parameters into one `SceneObject`
- Keep the initial sphere-and-ground image unchanged during the refactor
- Update Constant Buffer data by iterating the scene object collection
- Submit Draw Calls by iterating the same scene object collection
- Preserve the current HLSL, moving Directional Light, depth test, and `N` normal debug view
- Follow with a learner-authored second sphere and simple runtime parameter controls

No model importer, entity-component system, scene serialization, editor UI, Cook-Torrance BRDF, texture, or third-party dependency is part of this task.

## Current step acceptance criteria

1. Each object contains an explicit mesh range, transform, and material parameter group.
2. Constant Buffer updates and Draw Calls use the same `sceneObjects_` collection.
3. The sphere and ground retain their existing transforms and material values.
4. Chinese comments explain the object-data relationship without introducing a generic engine architecture.
5. CMake, MSVC, and DXC builds pass with warnings treated as errors.
6. The existing scene and `N` normal debug view still render correctly.
7. `git diff --check` passes.

## Follow-up learner exercise

- Increase the scene object count
- Add a second sphere entry using the existing sphere mesh range
- Give it a distinct transform, base color, roughness, and specular strength
- Build, run, inspect, and adjust the result
- Add runtime selection and parameter controls after the static object is understood
